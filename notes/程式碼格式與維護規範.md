# 程式碼格式與維護規範

本規範適用 `weather-order-assistant-system`。目的為讓不同模組保持一致、方便後續維護；**排版整理不應改變商業規則、資料庫結構或使用者操作流程**。

## 1. 共通規則

- 使用 **UTF-8、LF 換行、四個空白縮排**，不使用 Tab。
- 每個程式檔以一個換行字元結尾，避免行尾多餘空白。
- 不任意更動已存在的字串、使用者提示、ID、CSS class、HTML 屬性、API 路徑或事件名稱。
- 註解使用**繁體中文**描述「為何這樣做」及必要的商業規則；避免僅重述下一行的程式碼。
- 一個模組只負責一類功能。共同處理程式集中到既有 `common.js`，不要把所有頁面功能塞回 `app.js`。
- 不為了排版修改資料庫版本檔、產生的圖片，或 Maven/PowerShell/Shell 的執行行為。

## 2. Java（Entity、Repository、Service、Controller、DTO、測試）

- `package` 在最上方；`import` 分組排序：`static` → `java/javax` → `jakarta` → `org` → `com` → `tools` → `lombok`，不同組之間保留空白行。
- 類別、方法、條件式及區塊以四空白縮排；同層級的 `@Annotation` 與所修飾的宣告保持一致的縮排。
- 公開方法若有必要，使用 JavaDoc `/** ... */` 說明輸入、限制與回傳；實作內的特殊判斷使用 `//`。
- Repository 內的多行 `@Query` 字串可能包含需要保留的空白；**不要為了排版而重寫 Java Text Block 內容**。
- 不變更原有方法名稱、回傳型別、查詢條件或例外處理。修改核心邏輯時另外設測試，不混在純排版提交中。

## 3. JavaScript

- 採原生 ES Modules，使用四空白縮排，頂層函式間隔一空白行。
- 多行 import 維持一項一行；長參數清單適度換行；保留模組化分工。
- 公開函式或複雜流程可使用 JavaDoc 形式的 `/** ... */`；函式內使用簡短的 `//` 中文註解。
- **原本字串的單／雙引號與模板字串內容原樣保留**，避免大規模重寫造成提示文案、正規表示式或 HTML 字串變動。
- 使用者可見的文案優先使用「無法載入資料、請重新查詢」等白話表述；`API`、`DTO`、`HTTP`、`後端` 等開發術語留給程式註解與開發工具，不放進提示視窗。
- 原本 `throw new Error`、`showMessage` 等錯誤處理流程保持不變；僅必要時調整對使用者顯示的訊息。

## 4. Thymeleaf HTML

- `<html>`、`<head>`、`<body>`、`<section>` 與其他容器依巢狀層級縮排；延伸屬性置於下一行並加一層縮排。
- 長篇 SVG 圖示拆成開頭、圖形元素、結尾三層顯示，但不修改 `path d` 或其他 SVG 屬性。
- **保留所有 `th:*`、`id`、`class`、`data-*`、`name`、表單元素及 `<script>` 引入順序**。
- 不自行翻譯或重寫使用者畫面文字；若需改善術語，應單獨在差異報告說明。
- 不重新格式化 `<textarea>`、`<pre>` 或其他空白具有意義的元素內容。

## 5. CSS

- 每組選擇器以自己的 `{}` 區塊呈現；屬性各占一行、縮排四格、冒號後加一個空白。
- 每組規則之間留一個空白行，`@media` 與其他巢狀區塊以四格縮排。
- **不變更選擇器、權重、宣告順序、數值、顏色、單位、動畫或媒體查詢條件**。
- 維持暖米白、奶茶棕與焦糖橘的視覺風格，不更換背景資產。

## 6. SQL 與設定檔的注意事項

- **Flyway `V001`～`V011` 已執行版本保持原檔 byte-for-byte 完全不動**，因為單純格式調整也可能改變 checksum，導致啟動時驗證失敗。
- 以後新增或修改資料表請新增下一份 Migration，不編輯已執行的舊版 SQL。
- `pom.xml` 只統一縮排，不變更版本、相依套件或建置設定。
- `application.properties` 保留全部設定值及環境變數；其 `spring.jpa.hibernate.ddl-auto=validate` 表示**檢查**資料表，不是自動更新。
- 專案 `.editorconfig`、`.vscode/settings.json` 設定統一縮排與換行，供後續開發使用。

## 7. 後續程式碼修改的原則

1. 先讀取使用者目前版本的檔案，不能直接以舊對話中提供的程式碼覆蓋。
2. 最小必要變更，保留使用者自行調整過的畫面文字。
3. 先用 `mvnw.cmd clean test` 驗證；再啟動 Spring Boot，以瀏覽器與 Postman 驗收操作。
4. 修改前後比較資料庫 Migration checksum、JavaScript 的實際 API 呼叫與 Thymeleaf 欄位名稱，避免排版時誤改功能。
5. 整理程式碼與實作新功能分成不同次變更，方便回溯與除錯。
