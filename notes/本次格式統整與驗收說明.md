# 本次專案格式統整與驗收說明

基準：使用者於 2026-11-22 上傳的 `weather-order-assistant-system(2).zip`。

## 一、已整理的內容

- 23 個 JavaScript：統一區塊縮排、函式段落、較長的 import 與部分長參數呼叫；**原有業務邏輯、事件及模組關係不變**。
- 2 個 Thymeleaf HTML：依 HTML 巢狀層級重排縮排；12 處長篇 SVG 圖示分行；保留所有屬性、連結與原有畫面文字（除明列的白話調整）。
- 6 個 CSS：將擠成單行的規則拆成標準多行，維持原選擇器、屬性、宣告順序及值。
- 101 個 Java 主程式／測試檔均檢視：原本已符合規範的檔案保留；其餘整理 import、空白、換行與少數測試註解／註記的排版。未重新撰寫方法邏輯。
- `pom.xml`：原 Tab 換成四個空白，只改排版。
- `application.properties`：修正一處可能讓人誤以為會自動更新資料表的舊註解，設定值完全不變。
- 新增 `.editorconfig`；補充 `.vscode/settings.json` 的編輯器設定。
- 原有 11 份 Flyway SQL、圖片、Maven Wrapper 與執行腳本**維持原內容不動**。

## 二、使用者可見的文字調整

這次**沒有重設既有提示文字**，僅將原本殘留的開發術語替換為較容易理解的表達。修改位置包括：

- `templates/index.html`：首頁訂貨提示的「後端規則式」改為「依據銷售、庫存與天氣資料」。
- `js/order-recommendation.js`：訂貨建議讀取失敗不再要求使用者「檢查後端版本／後端資料」。
- `js/weather.js`、`js/dashboard-overview.js`：天氣資料異常時不再顯示「天氣 API 回傳格式」。
- `js/common.js`：資料讀取／操作失敗改為一般使用者訊息，仍保留可供客服辨識的錯誤代碼。
- `js/help-dialogs.js`：本次倍率與每日平均不一致時，不再使用「後端」術語。
- `js/purchase-order-details.js`：採購明細讀取失敗不再顯示「API 未回傳 items」。
- `js/sales-record.js`：退貨說明改為「送出時仍會確認退貨條件」。
- `js/recommendation-order-draft.js`、`js/dashboard-recommendations.js`、`js/supplier.js`：改為請重新查詢或稍後重試。
- `js/demo-crud.js`：未接入正式主頁的舊版進階編輯工具，也移除使用者畫面中的 Request DTO、Controller、JSON 格式等技術說法；其資料輸入方式仍維持原本的進階格式。

開發者使用的 `API` 變數、`/api/...` 網址、`DTO` 類別，以及非顯示給使用者的技術註解均保留。

## 三、已完成的靜態驗證

- **JavaScript**：23/23 檔案經 Node 語法檢查；以「只替換上述文案」的原始檔做參照，23/23 的 TypeScript AST 結構相同。
- **Java**：主程式與測試共 101/101 檔案由 JDK 21 `JavacTask.parse()` 完成語法解析，無語法錯誤。
- **CSS**：6/6 檔案的 PostCSS AST 選擇器、屬性、值與順序和原始專案一致。
- **HTML**：`index.html`、`login.html` 的 HTML parser 元素、屬性和非空白文字節點與「僅白話文案變更」的原始專案一致。
- **資料庫**：11/11 份 Flyway SQL byte-for-byte 完全一致，包含原有換行格式。
- **資產**：商品貨架背景圖片位元組內容一致。
- **設定**：`pom.xml` 可正常解析，所有 JS 相對 import 可找到檔案；原始專案檔案均有保留。

**未執行**：Maven 完整編譯／JUnit、連接 MySQL、Spring Boot 啟動、Postman 與瀏覽器操作驗收。此環境缺少可直接使用的 Maven 建置環境與專案資料庫，無法將靜態檢查等同於完整驗收。

## 四、建議本機驗收

1. 將目前已驗收的專案先備份，選擇「完整整理版」或「僅修改檔案補丁」其中一種套用方式。
2. 在 Windows 專案根目錄執行：

   ```powershell
   .\mvnw.cmd clean test
   ```

3. 啟動 Spring Boot，確認 Flyway 沒有 checksum 錯誤。
4. 瀏覽器檢查登入／登出、首頁、天氣預報、天氣訂貨、商品分類、商品、供應商、銷售、採購單、說明視窗。
5. 特別檢查 JS 改版時曾自行修改的訊息文字、日曆與日期提示、退貨條件、編輯視窗及下載報表功能。
6. Postman 重測多商品銷售、庫存與退貨、建立及提交訂貨單、修改密碼後 Session 失效等核心流程。
